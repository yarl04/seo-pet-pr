# Что приготовить за 30 минут

Учебный каталог из 12 рецептов для практики HTML-семантики, SEO и доступного кастомного комбобокса. Astro генерирует готовые HTML-страницы. JavaScript загружается только в каталоге для поиска и фильтров; React, сервер и база данных не нужны.

## Запуск

Нужны Node.js 20.19+ и npm.

```sh
npm i
npm run dev
```

Откройте `http://localhost:4321/seo-pet-pr/` (путь задаётся параметром `base` в `astro.config.mjs`). Для просмотра production-сборки:

```sh
npm run build
npm run preview
```

Внутренние ссылки и пути к файлам из `public/` формируйте через `withBase()` из `src/lib/urls.ts`: например, `withBase('/recipes/')`. Функция использует `import.meta.env.BASE_URL` и не добавляет префикс повторно. Для абсолютных SEO-адресов используйте `absoluteUrl()` из `src/lib/seo.ts`.

## Что реализовано

- Главная, каталог, отдельные страницы завтраков, обедов и ужинов, 12 рецептов и страница 404.
- Поиск по названию и ингредиентам, фильтры категории, основного ингредиента, времени и блюд без мяса и рыбы. Фильтры пересекаются, сохраняются в URL и восстанавливаются при перезагрузке и возврате из рецепта.
- Понятное пустое состояние и полный сброс фильтров.
- Статический контент и навигация доступны без JavaScript. В этом режиме фильтры скрыты, вместо них показано пояснение; поиск требует JavaScript.
- Адаптивная вёрстка, видимый фокус, ссылка перехода к содержимому, локальные шрифты и изображения, стили печати рецептов.
- Уникальные title/description, canonical без параметров фильтрации, Open Graph и Twitter Card. JSON-LD `Recipe`, `BreadcrumbList` и `ItemList` генерируется из тех же данных, что и видимый контент. Рейтинг и пищевая ценность не выдумываются.

## Структура

```text
src/
  components/     Шапка, подвал, хлебные крошки, карточки, фильтры
  data/           Рецепты и категории — единый источник данных
  layouts/        Общая структура документа и метаданные
  lib/            Чистые функции фильтрации, URL и JSON-LD
  pages/          Статические маршруты, sitemap.xml и robots.txt
  scripts/        Поведение каталога и комбобокса
  styles/         Общие токены, компоненты и адаптивная вёрстка
  types/          Модели данных и интерфейсы компонентов
public/images/    Локальные фотографии блюд
tests/            Браузерные проверки Playwright и axe-core
docs/             Ручная проверка доступности и источники фотографий
tasks/            План, результаты и уроки
```

Чтобы добавить рецепт, создайте запись в `src/data/recipes.ts` и добавьте фотографию в `public/images/`. Страница, карточки, sitemap и JSON-LD появятся при следующей сборке. Фотография должна соответствовать блюду; `imageAlt` описывает её существенное содержимое.

## Семантика и комбобокс

Общий `header` — шапка, `main` — содержимое, `footer` — подвал. У основного `nav`, хлебных крошек и навигации по категориям разные доступные названия. Один `h1` на страницу; разделы используют `h2`, вложенные карточки и шаги — `h3`. Рецепт размечен `article`, ингредиенты — `ul`, шаги — `ol`. `aside` используется для дополнительных советов.

`main` и `nav` не имеют дублирующих ARIA-ролей. `role="list"` на некоторых стилизованных списках сохраняет их объявление в Safari/VoiceOver при `list-style: none`. Декоративные стрелки, таймер и дублирующие миниатюры не создают лишних объявлений.

Комбобокс ингредиента самостоятельно реализован по [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). Нативный `select` хранит выбранное значение; после инициализации его интерфейс заменяется полем с `role="combobox"` и списком `listbox`/`option`. Остальные селекты и checkbox остаются нативными.

| Действие | Поведение |
| --- | --- |
| Ввод текста | Поиск по вариантам, без автоматического выбора первого |
| Стрелки вниз/вверх | Открытие списка и перемещение активной подсказки |
| Enter | Подтверждение активного варианта |
| Escape | Закрытие списка, восстановление подтверждённого значения |
| Tab / уход из поля | Закрытие без подтверждения подсказки, обычное движение фокуса |
| Очистка поля | Снятие фильтра ингредиента |
| Выбор указателем | Подтверждение варианта, фокус остаётся в поле |

Выбирается только существующий ингредиент. DOM-фокус остаётся в поле, активная подсказка обозначается `aria-activedescendant` и `aria-selected`. Результат фильтрации объявляется через `role="status"`; подсказки не входят в Tab-порядок.

## Проверки

```sh
# Один раз, если Chromium ещё не установлен:
npx playwright install chromium

# Проверка TypeScript/Astro, production-сборка и все браузерные тесты:
npm run verify
```

Отдельно доступны `npm run check`, `npm run build`, `npm test`. Тесты запускают локальный сервер production-сборки; перед отдельным `npm test` выполните сборку. В CI лучше использовать `npm run verify`. При нехватке системных библиотек браузера используйте `npx playwright install --with-deps chromium` в окружении, где разрешена установка пакетов ОС.

Тестовый сервер использует отдельный порт 4322. Для дополнительной проверки размещения в корне домена выполните `npm run build -- --base /`, затем `TEST_BASE=/ npm test`. После этого `npm run build` восстановит сборку с `base` из конфигурации.

Тесты проверяют все содержательные страницы, метаданные, локальные изображения и внутренние маршруты, соответствие Recipe видимому тексту, комбобокс, поиск/фильтры/URL, skip-link, работу без JavaScript, отсутствие горизонтального переполнения и правила WCAG 2.2 AA через axe-core. Автоматические проверки не заменяют [ручную проверку скринридером](docs/accessibility-checklist.md).

## Подготовка к публикации

Перед сборкой задайте настоящий корневой адрес сайта:

```sh
SITE_URL=https://your-domain.example npm run build
```

Публикуйте содержимое `dist/` на статическом хостинге. Хостинг должен отдавать `404.html` с HTTP-статусом 404 для неизвестных адресов и обслуживать вложенные `index.html`. Не включайте SPA-перенаправление всех адресов на главную.

Без `SITE_URL` используется `http://localhost:4321`; такая сборка намеренно имеет `noindex` и `Disallow: /`. Для рабочего домена индексация открывается автоматически, кроме 404. В `.env.example` показан формат переменной; команда выше передаёт её непосредственно конфигурации Astro. Параметры фильтров не создают отдельные индексируемые страницы; каноническая страница — `/recipes/`.

После публикации проверьте URL рецепта в [Google Rich Results Test](https://search.google.com/test/rich-results) и отправьте `sitemap.xml` в Search Console. Локальные тесты проверяют структуру JSON-LD и совпадение с содержимым, но не подтверждают доступность опубликованного сайта для Google и не гарантируют расширенные результаты. Требования к Recipe: [Google Search Central](https://developers.google.com/search/docs/appearance/structured-data/recipe).

Источники изображений и условия использования перечислены в [docs/image-credits.md](docs/image-credits.md). Шрифты Manrope и Golos Text поставляются локально через Fontsource под OFL; копии лицензий включены в `public/licenses/` и production-сборку.
